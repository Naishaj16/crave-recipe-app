T1. Mobile cellular network architecture

Definition

A mobile cellular network divides a service area into cells, each served by a low-power base station that handles calls for the users inside it.

Introduction

Cellular design solves the capacity problem of one large transmitter. Small cells let the same frequency be reused in distant cells, and the network hands a call from one cell to the next as the user moves.

Key points

  • Mobile Station (MS): the handset plus SIM, which holds the subscriber identity.
  • BTS (base transceiver station): the radio equipment at each cell site, sending and receiving on the air interface.
  • BSC (base station controller): controls several BTSs, allocates radio channels and manages handover between them.
  • MSC (mobile switching centre): switches calls and connects the network to the PSTN and the Internet.
  • HLR (home location register): stores permanent subscriber data such as the IMSI and services bought.
  • VLR (visitor location register): stores temporary data for users currently in the MSC's area.
  • EIR (equipment identity register): keeps IMEI white, grey and black lists to block stolen handsets.
  • AuC (authentication centre): holds the keys used to authenticate subscribers.
  • Call path: MS → BTS → BSC → MSC. The MSC checks the HLR, VLR, AuC and EIR before it sets up the call.
  • Handover: when the signal from a neighbouring cell is stronger, the BSC moves the call to that cell without dropping it.

Advantages

  • Frequency reuse gives high total capacity in a limited spectrum.
  • Small cells give good signal strength and low transmit power, which saves battery.
  • Handover gives continuous service while the user moves.

Disadvantages

  • Many base stations are needed, so infrastructure and maintenance cost is high.
  • Co-channel interference and handover failures appear in dense areas.
  • The radio link is open, so it can be eavesdropped unless encrypted.

Conclusion

The cellular architecture gives capacity and mobility, but its components (HLR, VLR, AuC, EIR) are also the points that security must protect.

T2. Generations 0G–6G and access techniques

Definition

Mobile generations are successive standards for cellular networks. Each one adds new services, higher speeds and, from 2G on, stronger security.

Introduction

Every generation was built to fix a weakness of the previous one. 1G carried analog voice with no security at all. Each later generation added a new protection, which is why the security story of mobile networks is a story of successive fixes.

Key points

  • 0G: early mobile telephones (radio-telephone systems) with manual connection and no roaming.
  • 1G (1980s): analog voice only, about 2.4 kbps, with no encryption, so calls could be heard with a scanner.
  • 2G (1990s): digital voice and SMS, with basic one-way authentication and encryption (A5), about 9.6–64 kbps.
  • 2.5G / 2.75G: GPRS and EDGE add packet data to GSM.
  • 3G (UMTS): mobile internet and video calls, with mutual authentication, about 2 Mbps.
  • 4G (LTE): all-IP network with VoLTE, EPS-AKA authentication and AES encryption, about 100 Mbps to 1 Gbps.
  • 5G: massive IoT, latency around 1 ms, network slicing and better subscriber privacy through SUCI.
  • 6G: research stage, expected to use AI and terahertz frequencies.
  • FDMA: each user gets its own frequency band (used in 1G).
  • TDMA: users share one frequency in turns, each with a time slot (used in 2G).
  • CDMA: all users transmit together on the same band, each with a unique spreading code (used in 3G).

Advantages

  • Each generation is faster, supports more services and adds protection.
  • Access techniques let many users share limited spectrum efficiently.
  • Later generations (3G onward) remove the basic weaknesses of earlier ones.

Disadvantages

  • Legacy 2G and 3G stay on air, so attackers can force a phone to downgrade to the weaker network.
  • Each new generation needs new infrastructure, which is costly for operators.
  • 5G and 6G increase the number of connected devices, so the attack surface grows.

Conclusion

Each generation improved speed, capacity and security, but legacy networks left open paths for downgrade attacks. Security must be judged across all generations in use, not just the newest.

T3. IEEE wireless standards

Definition

The IEEE 802 wireless standards are a family of specifications, each designed for a particular coverage area, from a personal device to a whole city.

Introduction

The family is organised by range. Personal-area networks connect a few nearby devices, local-area networks cover a building, metropolitan networks cover a city, and mobile standards cover users moving at speed. Choosing the right standard depends on the distance and the mobility needed.

Key points

  • 802.11 (Wi-Fi): the WLAN standard, operating in the 2.4 and 5 GHz bands, with versions such as 802.11a/b/g/n/ac/ax.
  • 802.15 (WPAN): personal-area networks; Bluetooth is 802.15.1 and ZigBee is 802.15.4 (low-power sensors).
  • 802.16 (WiMAX): metropolitan broadband, covering kilometres, for fixed and then mobile users.
  • 802.20 (MBWA): mobile broadband wireless access, designed for high-speed moving users such as trains; it was not widely adopted.
  • 802.21 (MIH): Media Independent Handover; it lets a device move a session between Wi-Fi, cellular and Ethernet without losing it.
  • MIH services: MIES (events, such as a link going down), MICS (commands, such as switching networks) and MIIS (information about nearby networks).
  • The standards share a common MAC design where possible, so devices can work across them.

Advantages

  • Standards cover every range, from personal devices to metropolitan networks.
  • Common design principles make equipment interoperable across vendors.
  • 802.21 keeps sessions alive while a device changes network.

Disadvantages

  • Overlapping standards make it confusing to choose the right one.
  • 802.20 never gained wide adoption, so its benefits were not realised.
  • 802.16 at higher frequencies needs a clear line of sight.

Conclusion

The IEEE 802 family covers the full range of wireless needs. Each standard has its own security model, so a network that uses several must secure each link separately.

T4. IEEE 802.11 architecture and frame

Definition

IEEE 802.11 is the standard for wireless local area networks. It defines the stations, access points, network structures and MAC frame format that operate at the data link layer.

Introduction

A Wi-Fi network is built from stations that share a radio medium. Before sending data, a station must authenticate and then associate with an access point, and every frame it sends has a fixed structure that carries addressing, sequence and security information.

Key points

  • Station (STA): any device with an 802.11 radio, such as a laptop or phone.
  • Access point (AP): a station that bridges wireless traffic to the wired distribution system.
  • Distribution system (DS): the wired backbone that links APs together.
  • SSID: the network name broadcast in beacon frames.
  • Infrastructure BSS: stations communicate through an AP; the normal setup for homes and offices.
  • IBSS (ad hoc): stations communicate directly with each other, without an AP.
  • ESS: several BSSs joined by a DS under one SSID, so a device can roam between APs.
  • Authentication then association: the station first proves its identity, then associates with an AP to receive network service.
  • Frame fields (nine): Frame Control (includes the WEP bit, showing that the security mechanism is applied); Duration/ID; Addresses 1–4; Sequence Control (12-bit sequence number to filter duplicates, 4-bit fragment number); Frame Body (data); and the 32-bit FCS (CRC) for error detection.
  • Layer: 802.11 works at the data link layer (MAC and LLC) and the physical layer below it.

Advantages

  • The infrastructure mode centralises control and security at the AP.
  • The ESS structure lets users roam across a large building with one network name.
  • The frame structure supports duplicate filtering and error detection.

Disadvantages

  • The radio medium is shared, so stations contend for it and collisions reduce throughput.
  • Frame headers are visible to anyone in range, so traffic can be captured.
  • A rogue AP using the same SSID can imitate a real network and attract users.

Conclusion

The 802.11 architecture gives a flexible, roaming-capable network, but its shared radio medium and visible frame headers make security measures such as WEP, WPA and 802.11i necessary.

Unit I

T5. Mobile internet networks

Definition

Mobile internet is the use of Internet services over cellular radio links while the user is moving, supported by a core network that routes, authenticates and bills the traffic.

Introduction

When a user opens a web page on a phone, the request crosses several networks. Each stage adds a security and mobility role, so the path is a useful way to see where protection must be applied.

Key points

  • Path: smartphone (with SIM) → radio link → base station (eNodeB in LTE, gNodeB in 5G) → core network → Internet gateway → web server.
  • Radio link: encrypted on the air interface, using the cipher negotiated for that generation.
  • Core network: checks the subscriber, tracks location for mobility, routes packets and records usage for billing.
  • Internet gateway: connects the operator network to external IP networks; a common place for firewalls.
  • Technologies: GPRS and EDGE (2G/2.5G), 3G UMTS, 4G LTE and 5G.
  • Challenges: congestion when many users share one cell, weak indoor coverage, battery drain from constant connection.
  • Threats: phishing and malware through apps, fake Wi-Fi hotspots, and location tracking by the operator or an attacker.
  • Security needs: confidentiality of data, integrity of messages, authentication of both ends, availability of service, and privacy of location and identity.

Advantages

  • Users can reach Internet services anywhere, while moving.
  • It supports cloud services, navigation and location-based apps.
  • The core network provides central control over authentication and billing.

Disadvantages

  • Shared cell capacity leads to congestion at peak times.
  • The operator can track location, which affects privacy.
  • Constant connection drains the battery and raises the exposure to attacks.

Conclusion

Mobile internet connects users to the world from anywhere, but every stage of the path needs its own protection, from the radio link to the application.

T6. Attacks and defences on cellular networks

Definition

Cellular network attacks try to intercept, track, impersonate or disrupt mobile users and services, using the radio interface, the signalling network or the core.

Introduction

Cellular networks carry voice, messages and banking traffic over open radio, and they rely on signalling between operators. Attacks can therefore start at the air interface or inside the core, and defences must be layered to match.

Key points

  • Eavesdropping: capturing the radio signal to read calls and messages. Defence: air-interface encryption (A5, UEA, EEA).
  • IMSI catcher (fake base station): a rogue transmitter that forces a phone to reveal its IMSI and location. Defence: mutual authentication, so the phone checks the network.
  • Man-in-the-middle: relaying and altering traffic between two parties. Defence: strong authentication and end-to-end encryption.
  • Replay: resending a captured valid message. Defence: timestamps, sequence numbers and nonces.
  • Denial of service: overloading the cell or core so users cannot connect. Defence: firewalls, intrusion detection, rate limiting and anomaly detection.
  • SS7 attacks: abuse of the signalling network that connects operators, to track users or intercept calls and SMS. Defence: signalling firewalls and operator filtering.
  • Malware: malicious apps that read messages or steal credentials. Defence: app vetting, permission control and updates.
  • Impact example: an IMSI catcher reveals the subscriber's identity and location before encryption starts, so the attacker can then track or target the user.
  • Layered defence: radio layer (encryption and mutual authentication); network layer (firewalls, intrusion detection, signalling filters); application layer (secure coding, permission control).

Advantages (of layered defence)

  • A breach in one layer can still be stopped by another.
  • Each layer can be tuned to the threats it faces.
  • Mutual authentication defeats fake base stations at the source.

Disadvantages

  • Many layers add cost, configuration work and complexity.
  • Old signalling protocols such as SS7 are hard to change, so some attacks persist.
  • Downgrade to older networks can bypass the stronger protections.

Conclusion

Cellular attacks exploit the radio link, the signalling network and the user. The strongest defence is layered: mutual authentication and encryption at the radio layer, filtering at the signalling layer, and secure applications on the phone.

T7. Wired vs wireless security

Definition

Wired security protects a network mainly through physical access control to cables, ports and rooms. Wireless security must protect signals that travel through open air to any receiver in range.

Introduction

In a wired office, an attacker must reach a cable or switch port, so physical security is a strong first defence. A Wi-Fi signal leaves the building, so a person in the car park can capture traffic without ever entering. The security model must therefore change from controlling access to the cable to controlling who can read and send the radio signal.

Key points

  • Access medium: wired networks need physical access to a cable; wireless signals reach anyone in range.
  • Boundary: a wired network has a clear physical edge; a wireless network's edge is its radio range, which is hard to control.
  • Eavesdropping: capture is passive and undetectable in wireless networks; in wired networks, it needs a tap or a compromised switch.
  • Mobility: wireless devices move between access points, creating handover points that an attacker can exploit.
  • Device limits: handsets have limited battery and processor power, which restricts how heavy the security can be.
  • Jamming: wireless networks can be disrupted by radio interference, which has no direct wired equivalent.
  • Response: wireless needs encryption, strong authentication and access control, because physical protection no longer covers the medium.

Advantages (of wireless)

  • Mobility and no cabling, so networks are cheap to extend.
  • Quick to deploy in places where cabling is hard.

Disadvantages (of wireless security)

  • Easier to eavesdrop, intercept and jam.
  • Harder to control who connects and to detect unauthorised devices.

Conclusion

Wired security depends on physical control; wireless security depends on cryptography and authentication, because the signal is always reachable.

T8. Security issues and security requirements

Definition

Security issues are the threats that can harm a mobile network or its users. Security requirements are the properties the network must have to counter those threats.

Introduction

Mobile communication needs the classic CIA triad, extended with authentication, authorisation, non-repudiation and privacy. Each requirement answers one or more of the issues, and the balance between them depends on how the network is used.

Key points

  • Security issues: signal interception, unauthorised access, identity theft, SIM or device cloning, rogue access points, session hijacking, and loss of devices that hold banking data.
  • Confidentiality: data can be read only by the intended receiver, achieved by encryption (A5, UEA, EEA, AES).
  • Integrity: data cannot be changed unnoticed, achieved by message integrity codes such as UIA, EIA or CCMP.
  • Availability: services remain usable, which requires protection against denial of service and jamming.
  • Authentication: both user and network prove identity; mutual authentication stops fake networks.
  • Authorisation: after identity is confirmed, the user receives only the rights needed (least privilege).
  • Non-repudiation: a sender cannot deny sending a message, usually through digital signatures; this matters for payments.
  • Privacy: identity and location are protected, for example by using a temporary identity such as TMSI or GUTI.
  • Secure handover: the session moves to a new cell or network without being exposed or dropped.

Advantages (of meeting the requirements)

  • Builds user trust and meets legal and regulatory compliance.
  • Reduces fraud, data loss and identity theft.

Disadvantages

  • Adds cost, battery use and processing delay.
  • Key management becomes complex as the number of devices grows.

Conclusion

Every issue maps to a requirement. A secure mobile network must meet all of them, because a weakness in one (for example, one-way authentication) can undo the others.

T9. Security for mobile applications and application-level security

Definition

Application-level security places protective controls inside the mobile app itself, so that data stays protected whatever the network does.

Introduction

Network security protects data only while it travels. Once it reaches the device, the app must protect it. Many breaches come from apps that store data in plain text, trust unchecked input or use weak authentication, so application-level security is a necessary layer.

Key points

  • Secure storage: never keep passwords or banking data in plain text; use the Keystore or the platform's secure storage.
  • Authentication: use strong passwords, biometrics or multi-factor authentication, and do not rely on a single weak check.
  • Secure transport: send all data over HTTPS or TLS, and pin the certificate where possible.
  • Input validation: check and sanitise all input to block injection (SQL, command) and buffer overflow.
  • Least privilege: request only the permissions the app needs at the time it needs them.
  • Session management: use short-lived tokens, log out inactive sessions and protect against session hijacking.
  • Testing and updates: test with static and dynamic tools, and patch vulnerabilities quickly.
  • Obfuscation: make reverse engineering harder, but do not rely on it alone.

Advantages

  • Protects data end to end, whatever the network.
  • Allows fine-grained access control by role and by function.
  • Defends against SQL injection, cross-site scripting and session hijacking.

Disadvantages

  • Developers must build and maintain every control.
  • Encryption and checks use battery and processor time.
  • Keys and certificates are difficult to manage across many devices.
  • Inconsistent implementation across apps creates weak points.

Conclusion

Application-level security is the last line of defence and the most direct protection for user data. It works best together with network-level security, not instead of it.

Unit II

T10. Basics of security and secure communication protocols

Definition

Mobile security protects smartphones and tablets from threats that could compromise data or device integrity. A secure communication protocol protects data in transit between two parties, providing confidentiality, integrity and authentication.

Introduction

Phones hold personal, financial and business data and are always connected, often to untrusted networks. Device security protects the phone itself, and secure protocols protect the data while it moves. Both are needed for a complete defence.

Key points

  • Main threats: malware, phishing, Wi-Fi snooping, data leakage through poor permissions, and loss or theft of the device.
  • TLS/SSL: a protocol that authenticates the server (and optionally the client) with certificates and encrypts the channel, used for web, email and messaging.
  • HTTPS: HTTP carried over TLS, the standard way to protect web traffic on a phone.
  • VPN: creates an encrypted tunnel from the device to a trusted endpoint, protecting traffic on untrusted networks such as public Wi-Fi.
  • Device practices: PIN or biometric lock, full-disk encryption, permission control, remote wipe through MDM, prompt updates, installing only from trusted stores, and two-factor authentication.
  • Protocol goals: confidentiality (encryption), integrity (MAC or AEAD), authentication (certificates or keys) and replay protection (nonces or sequence numbers).

Advantages

  • Strong, widely supported encryption protects data in transit.
  • A VPN hides traffic from local attackers on public Wi-Fi.

Disadvantages

  • A VPN moves trust to its provider and endpoint.
  • Certificate warnings can confuse users and lead them to accept unsafe connections.
  • Encryption and handshakes add overhead on slow links.

Conclusion

Secure protocols protect data in motion, and device security protects data at rest. A mobile user needs both, plus careful habits on untrusted networks.

T11. Authentication and authorisation

Definition

Authentication confirms who a party is. Authorisation decides what that authenticated party is allowed to do.

Introduction

Authentication is always the first step: an unknown party cannot be given rights. Authorisation then applies rules to the verified identity, so the same person can have different rights in different parts of a system. Together they protect against identity theft and data leaks.

Key points

  • Authentication factors: something you know (password or PIN), something you have (SIM, token, phone), something you are (fingerprint, face).
  • Multi-factor authentication: combines two or more factors, so one stolen factor is not enough.
  • Mutual authentication: both sides verify each other; in mobile networks, the phone checks the network as well as the reverse, which stops fake base stations.
  • Authorisation: access control by roles and permissions; for example, a student can view marks but not edit them.
  • Least privilege: each user, process or app gets only the access needed for the task.
  • Separation of duties: critical actions need more than one party, which reduces insider fraud.
  • Why it matters: authentication stops impostors, and authorisation limits what a compromised account can damage.

Advantages

  • Multi-factor authentication is much harder to defeat than a password alone.
  • Role-based authorisation makes access easy to manage and audit.

Disadvantages

  • Passwords are often weak or reused across services.
  • SIM swapping can bypass SMS codes.
  • Biometrics can give false matches and raise privacy concerns about stored templates.

Conclusion

Authentication establishes trust and authorisation controls it. A secure mobile system needs strong, mutual authentication and carefully limited rights.

Unit II

T12. Challenges of cybersecurity and mobile security risks

Definition

Mobile cybersecurity challenges are the factors that make mobile devices hard to protect. Mobile security risks are the specific threats that exploit those factors.

Introduction

Mobility, personal use, open networks and rapid software change make phones a prime target. The challenges come from the device, the network, the apps and the people who use them, so the risks cover all four.

Key points

  • Device loss and theft: a lost phone exposes data unless it is encrypted and can be wiped.
  • Untrusted apps and stores: malicious apps can appear in unofficial stores or pass review.
  • Insecure networks: public Wi-Fi and fake hotspots expose traffic.
  • BYOD: personal devices on corporate networks mix personal and business data.
  • Frequent updates and fragmentation: many versions and vendors mean some devices stay unpatched.
  • Weak authentication: reused or simple passwords and no second factor.
  • App-based risks: excessive permissions, insecure code and insecure storage.
  • Network-based risks: unsecured Wi-Fi, fake hotspots and Bluetooth exploits.
  • Social engineering: phishing by email and smishing by SMS, which trick users into giving credentials.
  • OS risks: rooting, jailbreaking and privilege escalation that bypass the sandbox.
  • Limited visibility: organisations cannot see or control most personal devices.

Advantages (of mobility that creates these risks)

  • Productivity, location services and constant access to information.

Disadvantages

  • Risks grow with every new app, network and user.
  • Users are often the weakest link, because they click links and grant permissions without thinking.

Conclusion

The challenges are technical and human. Protecting mobile users needs device controls, safe networks, careful apps and regular user training.

Unit II

T13. Incident response process

Definition

Incident response is the planned process for detecting, handling and learning from a security incident, so that damage is limited and the incident does not recur.

Introduction

A mobile incident, such as a stolen phone with banking apps or an infected corporate device, can spread quickly. A tested process lets the team respond in a set order rather than improvising. The NIST SP 800-61 model describes six stages.

Key points

  • Preparation: written policies, tools for logging and analysis, backups, and a trained response team.
  • Detection and analysis: identify the incident from alerts or user reports, judge its severity, and collect evidence without destroying it.
  • Containment: stop the spread by isolating the device from the network, disabling the affected account, or revoking access tokens.
  • Eradication: remove the cause, such as malware, a malicious app or a vulnerable setting.
  • Recovery: restore systems from clean backups, reset credentials and monitor closely for repeat activity.
  • Lessons learned: review what happened, record findings, and update policy and training.
  • Example: a lost company phone is reported; the team remote-wipes it, revokes its certificates, checks logs for accesses, and updates the BYOD policy.

Advantages

  • Faster and more consistent response than ad hoc action.
  • Good records support audits, legal needs and future prevention.

Disadvantages

  • Depends on trained staff and continuous monitoring.
  • Hard to apply to personal (BYOD) devices that the organisation does not control.
  • Costly to maintain and test regularly.

Conclusion

Incident response turns a security breach into a managed event. Its value depends on preparation before the incident and on the lessons learned after it.

T14. GSM security

Definition

GSM security is the set of mechanisms that authenticate the subscriber to the network, encrypt the radio link and protect the subscriber's identity, based on a secret key Ki stored in the SIM and the network.

Introduction

GSM was the first digital cellular standard with security built in. Its design used challenge-response authentication and a stream cipher on the air link. The design was strong for its time but has known weaknesses, and it is the base on which GPRS and 3G were built.

Key points

  • Shared secret: Ki is stored in the SIM and the AuC, and never sent over the air.
  • Challenge: the network sends a random number RAND to the phone.
  • A3 (authentication): the SIM computes SRES from RAND and Ki; the network compares it with its own result. Only then is the phone accepted.
  • A8 (key generation): produces the ciphering key Kc from RAND and Ki.
  • A5 (encryption): a stream cipher encrypts the air link using Kc. A5/1 is the strong-export version and is weak; A5/2 is weaker and A5/3 is stronger.
  • Anonymity: the IMSI is sent rarely; a temporary identity TMSI is used for most messages.
  • One-way authentication: only the phone is checked; the phone does not authenticate the network.
  • No integrity: control messages are not protected against modification.
  • Steps to secure GSM: keep Ki secret in the SIM and AuC; use TMSI; avoid downgrade to A5/0 or 2G; move to 3G or LTE, which add mutual authentication.

Advantages

  • Simple and widely deployed, with the secret held in tamper-resistant SIM hardware.
  • TMSI limits how often the permanent identity is exposed.

Disadvantages

  • One-way authentication lets a fake base station pass as the network.
  • A5/1 is weak and can be broken by an attacker with the right equipment.
  • No end-to-end encryption and no integrity on signalling.

Conclusion

GSM introduced SIM-based authentication and air-link encryption, but one-way authentication and weak ciphers made it vulnerable. Its successors fixed these problems.

Unit II

T15. GPRS security

Definition

GPRS (General Packet Radio Service) adds packet data to GSM. Its security extends GSM's mechanisms to the packet core, which connects the phone to external IP networks.

Introduction

GPRS lets a phone send and receive IP packets, so it needs a core that routes packets. This adds nodes and links that GSM did not have, and each one brings new exposure. GPRS security therefore inherits GSM's strengths and weaknesses and adds some of its own.

Key points

  • Inherited mechanisms: Ki-based authentication, A3/A8 for the key, and TMSI for identity protection.
  • SGSN (serving GPRS support node): delivers packets to and from the phone and manages its mobility and authentication.
  • GGSN (gateway GPRS support node): connects the packet core to external IP networks such as the Internet.
  • GEA algorithms: GEA1, GEA2 and GEA3 encrypt packet data between the phone and the SGSN; some references add GEA4.
  • Encryption gap: the link between the SGSN and GGSN is not encrypted, so packets are exposed inside the core.
  • No end-to-end protection: data is protected only over the radio and up to the SGSN.
  • Fake base stations: the one-way authentication of GSM still allows IMSI catchers.
  • GSM vs GPRS: GSM protects a circuit-switched voice call; GPRS protects packet data, which passes through more nodes and is therefore more exposed.

Advantages

  • Always-on packet data, and efficient use of the radio channel.
  • Inherits the SIM-based identity of GSM.

Disadvantages

  • No encryption between SGSN and GGSN, so core traffic can be sniffed.
  • No end-to-end encryption and no mutual authentication.
  • Weaker than UMTS on every security measure.

Conclusion

GPRS brought packet data to mobile phones but added exposure in the core. It shows why security must cover every node on the path, not just the radio link.

Unit II

T16. 3G security

Definition

3G (UMTS) security provides mutual authentication through AKA, stronger encryption and integrity protection for signalling, and identity protection through temporary identities.

Introduction

3G was designed to fix the weaknesses of GSM and GPRS. Its main change is that the phone also checks the network, which defeats fake base stations. It also adds integrity protection, which GSM never had, and stronger ciphers.

Key points

  • Mutual authentication (AKA): the USIM and the Home Network both prove knowledge of shared secrets, so a fake station fails.
  • Authentication vectors: the Home Network generates vectors with RAND, AUTN, XRES and keys, and the Serving Network uses them to authenticate the user.
  • Encryption: UEA1 (based on the KASUMI block cipher) and UEA2 (based on SNOW 3G), with 128-bit keys.
  • Integrity: UIA1 and UIA2 protect signalling messages against modification and replay.
  • Identity protection: TMSI is used for most messages, and the IMSI is sent rarely.
  • USIM: the successor to the SIM; it stores the IMSI, the key K and the algorithms.
  • Home Network: the operator's core that authenticates the user and generates vectors.
  • Serving Network: the network currently giving service, which relies on the Home Network's vectors.
  • Remaining issue: 3G still allows a downgrade to 2G, where the stronger protections are lost.

Advantages

  • Mutual authentication and integrity protection for signalling.
  • Stronger 128-bit encryption than GSM.

Disadvantages

  • The downgrade path to 2G remains open to attack.
  • KASUMI is less trusted than newer ciphers, and some IMSI exposure is still possible.
  • Requires more network equipment and coordination than GSM.

Conclusion

3G is a major step: mutual authentication and integrity close the gaps that made GSM and GPRS easy to attack. Its remaining weakness is the fallback to older networks.

Unit II

T17. Android architecture and security model

Definition

Android is a mobile operating system built on the Linux kernel. Its architecture is layered, and its security model isolates each app and controls what it can access.

Introduction

Android's openness has helped it spread, and its security model must protect users in that open environment. The model works through the layers: the kernel isolates processes, the framework enforces permissions, and hardware-backed features protect keys and boot.

Key points

  • Applications layer: the apps the user installs and uses.
  • Application framework: provides services such as the Activity Manager and Content Providers, and enforces permission checks.
  • Native libraries and Android Runtime (ART): libraries such as WebKit and SQLite, and the runtime that runs app code.
  • Hardware Abstraction Layer (HAL): a standard interface between the framework and the device hardware.
  • Linux kernel: manages processes, memory, drivers and SELinux policy.
  • Sandbox: each app runs under its own Linux UID and process, so it cannot read another app's data by default.
  • Permissions: declared in the manifest; normal permissions are granted at install, and dangerous permissions (such as camera or contacts) are requested at run time from Android 6.0.
  • App signing: every app is signed; an update must carry the same signature.
  • SELinux: mandatory access control that limits what each process can do, even for the root user.
  • Verified boot and Keystore: verified boot checks each boot stage; Keystore stores keys in hardware-backed storage.

Advantages

  • Strong per-app isolation through the kernel.
  • Open platform with clear and user-visible permission controls.

Disadvantages

  • Fragmentation means many devices receive security updates late.
  • Sideloading and rooting can bypass the protections.

Conclusion

Android's security rests on the kernel sandbox, permissions, signing and hardware-backed keys. Its strength depends on the device staying updated and unrooted.

Unit II

T18. Fundamentals of Android development and securing apps

Definition

Android development builds apps from components that communicate through Intents. Securing an app means protecting its data, its components and its code.

Introduction

Apps are written mainly in Java or Kotlin and packaged as APK files. Each app is made of components, and the components talk to each other and to other apps through Intents. Every one of these links is a possible attack path, so the developer must secure them.

Key points

  • Activities: the screens of the app; they can be started by other apps if exported.
  • Services: background work, such as downloads or music playback.
  • Broadcast Receivers: respond to system or app events.
  • Content Providers: share structured data with other apps; a common source of leaks if not protected.
  • Intents: messages used to start components or pass data; implicit Intents can be intercepted by other apps.
  • Encrypt sensitive data with the Keystore instead of plain files or shared preferences.
  • Use TLS with certificate pinning for all network traffic.
  • Request only needed permissions; be especially careful with microphone, camera, contacts, location and SMS.
  • Restrict exported components and validate every incoming Intent and input.
  • Obfuscate the code with ProGuard or R8 to slow reverse engineering.
  • Never keep secrets in source code, resources or logs.

Advantages

  • Rich platform APIs for security, including the Keystore and the permission model.
  • Each component can be restricted on its own.

Disadvantages

  • An exported component opened by mistake can be abused by any app.
  • Security depends on developer discipline and regular review.

Conclusion

Secure Android development means limiting what each component exposes, protecting stored and transmitted data, and requesting only the rights the app needs.

T19. Android rooting

Definition

Rooting gives the user administrator (root) access to the Android system, usually by unlocking the bootloader and installing a su binary that grants root to chosen apps.

Introduction

Android is designed to limit the user and each app to a restricted set of rights. Rooting removes those limits. The gain is control, but many of the sandbox and integrity protections that protect the user depend on those limits, so rooting changes the security model.

Key points

  • How it is done: unlock the bootloader (which wipes the device), install a custom recovery, and install the su binary or a root manager.
  • Sandbox weakened: a root process can read the data of any app, which removes per-app isolation.
  • Malware route: malicious code only needs to obtain root once to gain full control.
  • Integrity checks fail: attestation and verified boot report the device as modified, so banking and payment apps may refuse to run.
  • Updates blocked or broken: system patches may fail, leaving known flaws open.
  • Exposure to SELinux changes: changing SELinux policy can disable mandatory access control.
  • Prevention: keep the device unrooted; use root detection and attestation in sensitive apps; install only from official stores; keep updates on.

Advantages

  • Full control of the device, including custom system settings.
  • Custom ROMs, removal of pre-installed apps and full-system backups.

Disadvantages

  • Much higher exposure to malware and data theft.
  • Voids the warranty and can break banking and payment apps.

Conclusion

Rooting trades the device's built-in protections for control. For a security-aware user, the risk is usually greater than the benefit, especially on a phone that holds banking data.

T20. Intercepting Android traffic and SSL pinning

Definition

Intercepting Android traffic means routing an app's network traffic through a proxy so that it can be inspected. SSL pinning means the app accepts only a known certificate or public key for its server.

Introduction

Testers and attackers both want to see what an app sends. Interception is an authorised testing technique; SSL pinning is the defence that stops a proxy or fake server from reading the traffic, even when the device trusts an extra certificate.

Key points

  • Setup (authorised testing only): run an interception proxy such as Burp Suite on a computer; point the device's Wi-Fi proxy to it.
  • Certificate: install the proxy's certificate as a trusted CA on the device so HTTPS traffic can be decrypted for inspection.
  • Pinning bypass in testing: if the app pins its certificate, tools such as Frida can disable the pin so the test can continue.
  • SSL pinning: the app compares the server certificate or public key with a stored value and refuses any mismatch.
  • Why pinning matters: a rogue trusted CA, or a user who installs a malicious certificate, cannot intercept a pinned app.
  • Tools in analysis: MobSF (static and dynamic scanning), Frida (runtime hooking), APKTool (decompiling), ProGuard (obfuscation).
  • What testers look for: cleartext traffic, weak TLS settings, accepted invalid certificates and secrets in traffic.

Advantages

  • Blocks man-in-the-middle attacks, even when a rogue CA is installed.
  • Testers can find pinning flaws and traffic problems before release.

Disadvantages

  • When the server certificate is rotated, the app breaks unless the pins are updated.
  • Makes debugging and support harder.
  • Can be bypassed on a rooted device with the right tools.

Conclusion

Interception shows where an app leaks data; SSL pinning stops the same interception from working against a real user. Developers should pin and manage pin rotation carefully.

T21. Attacks on Android

Definition

Attacks on Android exploit apps, components, storage, networks and the operating system to steal data or take control of the device.

Introduction

Most attacks rely on a user installing a malicious or over-permissioned app, on an insecure network or on a flaw in an app's own code. Knowing the common attack types helps developers test for them and users recognise them.

Key points

  • Malicious apps and repackaging: a legitimate app is decompiled, malicious code is added, and it is re-signed and distributed. Sideloading raises the risk.
  • Intent spoofing: a crafted Intent from another app forces an exported component to perform actions it should refuse.
  • Insecure data storage: passwords or tokens stored in plain files, shared preferences or external storage, which other apps or a thief can read.

  • Excessive permissions: an app with access to contacts, location and SMS can leak data even without an exploit.
  • Trojan apps: apps that work as advertised while hiding malicious code, such as spyware.

Advantages (for defenders)

  • Knowing these attacks guides secure coding, testing and user training.

Disadvantages (for users)

  • Attacks often succeed through apps that look normal.
  • Many attacks leave no visible sign on the device.

Conclusion

Android attacks combine app flaws, weak storage and user trust. Defence needs secure code, minimal permissions, safe transport and careful app installation.

T22. iOS security model and Android vs iOS

Definition

The iOS security model is a closed, hardware-rooted design in which Apple controls the software and the app store. Android is an open platform with a per-app sandbox and many device makers and stores. Comparing them shows the trade-off between control and openness.

Conclusion

iOS is stronger by default because the platform is controlled end to end. Android gives users more freedom, with more risk unless the user and the device maker keep it secure.

T24. Wi-Fi security introduction and security measures

Definition

Wi-Fi security protects wireless networks from unauthorised access and data breaches, using encryption, authentication and network segmentation.

Introduction

Radio signals reach everyone in range, so a Wi-Fi network needs protection against eavesdropping, intrusion and misuse. Some common measures look like security but give little real protection, so the answer must separate the real measures from the cosmetic ones.

Key points

  • Strong encryption: WPA2 with AES-CCMP or WPA3 with SAE.
  • Strong unique passphrase: long and random, since WPA2-Personal depends on it.
  • SSID hiding: reduces visibility but gives no real security, because the SSID appears in management frames.
  • MAC address filtering: easy to defeat, because an attacker can read an allowed address and spoof it.
  • Segmentation: separate guest and corporate networks through VLANs, so a breach stays contained.
  • 802.1X: per-user authentication for enterprise networks.
  • Admin hygiene: change the router's admin password, update firmware and disable WPS.

Advantages

  • WPA2 and WPA3 give real confidentiality and authentication.
  • Segmentation limits the spread of a breach.

Disadvantages

  • SSID hiding and MAC filtering give a false sense of security.
  • A weak passphrase defeats WPA2 and WPA3-Personal.

Conclusion

Real Wi-Fi security comes from strong encryption, strong authentication and segmentation. Cosmetic measures should never replace them.

T25. Active and passive attacks

Definition

A passive attack observes traffic without changing it. An active attack alters, injects or disrupts traffic or services.

Introduction

The difference decides which security goal is threatened and whether the victim notices. Passive attacks threaten secrecy quietly; active attacks threaten integrity and availability and usually leave evidence.

Key points

  • Passive attacks: eavesdropping, sniffing and traffic analysis, which learns patterns from who talks to whom and when.
  • Passive target: confidentiality; the victim usually does not know.
  • Active attacks: message modification, packet injection, rogue access points and deauthentication floods.
  • Active target: integrity and availability; the victim usually notices a disruption.
  • Masquerade and replay: active attacks that pretend to be another party or resend captured messages.
  • Defence against passive attacks: encryption, which makes captured data useless.
  • Defence against active attacks: integrity codes, authentication, protected management frames and intrusion detection.

Advantages (for the attacker)

  • Passive attacks are very hard to detect.
  • Active attacks can change data and disrupt services.

Disadvantages (for the attacker)

  • Passive attacks gain only what is visible, so encryption blocks them.
  • Active attacks leave traces and are easier to detect.

Conclusion

Passive attacks are about secrecy and are stopped by encryption. Active attacks are about control and are stopped by integrity, authentication and monitoring.

T26. Denial-of-service attacks

Definition

A denial-of-service (DoS) attack makes a network or service unavailable to its users by overwhelming it or exploiting a flaw that crashes it.

Introduction

Availability is one of the CIA requirements, and wireless networks are easy to disrupt because the radio medium is shared. DoS can target the radio, the management frames or the IP services, and each needs a different response.

Key points

  • Buffer overflow: sending oversized input that overwrites memory, crashing or stalling the target.
  • Flood attacks: saturating the target with packets; they succeed when the attacker has more bandwidth than the target.
  • Deauthentication flood: forged deauthentication frames disconnect clients from a Wi-Fi network repeatedly.
  • RF jamming: radio interference on the channel that stops all communication.
  • DDoS: many compromised sources attack at once, making the flood hard to block at one point.
  • Detection: repeated unexplained disconnections, many deauthentication frames, spikes in connection requests, and rising latency.
  • Mitigation: rate limiting, anomaly detection, protected management frames (802.11w), and WPA2 or WPA3.

Advantages (of the defences)

  • Rate limiting and 802.11w block many floods and forged frames.
  • Anomaly detection can spot new attack patterns early.

Disadvantages

  • DDoS is hard to stop at a single point.
  • Rate limiting can block legitimate users during busy periods.
  • RF jamming is hard to defeat without locating and removing the jammer.

Conclusion

DoS attacks are cheap and effective, so defence needs layered controls and monitoring at the radio, network and service levels.

T27. TCP attacks

Definition

TCP attacks exploit the way TCP sets up, tracks and ends connections, using spoofed packets, predicted sequence numbers and the handshake state.

Introduction

TCP trusts the addresses and sequence numbers in packets. A forger who can predict or see those values can take over a session, flood the server or end a connection, so TCP-level protection is needed on wireless links as well as wired ones.

Key points

  • Session hijacking: the attacker predicts the sequence numbers and sends spoofed packets, so the receiver accepts the attacker's data and drops the real sender's.
  • SYN flooding: many SYN packets with spoofed sources leave the server waiting for handshakes that never complete, filling its queue.
  • RST attack: forged reset packets end a session such as a VPN or SSH connection.
  • TCP spoofing: forged IP and sequence numbers inject data or gain access to a service.
  • Protection: run the session over IPsec or TLS, so forged packets fail authentication.
  • Random initial sequence numbers: make prediction much harder.
  • SYN cookies: let the server avoid storing half-open connections.
  • Filtering and monitoring: drop forged resets from unexpected sources and watch for anomalies.

Advantages (of the protections)

  • IPsec and TLS stop forged packets from being accepted.
  • SYN cookies protect the server queue without extra memory.

Disadvantages (of the protections)

  • Encryption adds overhead and some latency.
  • Protection does not cover unauthenticated traffic that is not wrapped.

Conclusion

TCP attacks succeed because TCP trusts its header fields. Cryptographic protection and random sequence numbers remove that trust.

T28. Trojan and dictionary attacks

Definition

A Trojan is malware disguised as legitimate software. A dictionary attack guesses a password by trying likely words, phrases and leaked passwords.

Introduction

Trojans rely on human error to install them, and dictionary attacks rely on weak passwords. Both are cheap and effective, which is why they remain common, and both can be countered with user training, strong authentication and account controls.

Key points

  • Trojan delivery: phishing emails, fake updates, or downloads from untrusted sites.
  • Trojan effect: opens a backdoor, steals data or damages the system while appearing to work.
  • Trojan prevention: antivirus, updated software, caution with unknown emails and downloads, and least privilege.
  • Dictionary attack: tries likely words with variations such as digits, capital letters or symbols.
  • Online attack: guesses against the live login; lockout and rate limiting slow it.
  • Offline attack: tests captured hashes or WPA2 handshakes on the attacker's own computer, so there is no lockout; a weak passphrase falls quickly.
  • Mitigation: long unique passphrases, WPA3 SAE (which resists offline guessing), account lockout and monitoring of repeated failures.

Advantages (of the defences)

  • WPA3 SAE resists offline dictionary attacks.
  • Account lockout stops online guessing.

Disadvantages

  • Humans are the weakest link against Trojans.
  • Dictionary attacks are cheap and automated.

Conclusion

Trojans and dictionary attacks both exploit trust and weak secrets. Technical controls and user habits must work together.

T29. IEEE 802.11 security: WEP to WPA3

Definition

IEEE 802.11 security is the set of mechanisms that protect WLAN traffic, developed from WEP through WPA, WPA2 and WPA3.

Introduction

Each generation fixed the flaws of the one before but raised new questions. The progression shows how a security design must be checked against real attacks, not just assumed to work.

Key points

  • WEP: RC4 stream cipher with a 24-bit initialisation vector (IV). The IV is too short and is reused, the CRC-32 integrity check is weak and can be forged, and the static key can be recovered from captured traffic. WEP is broken.
  • WPA: an interim fix using TKIP, which changes keys per packet and adds a message integrity code, but still uses RC4 and is now deprecated.
  • WPA2 (802.11i): AES in CCMP mode, giving confidentiality and integrity; the default for WPA2.
  • WPA2-Personal: uses a shared passphrase with the four-way handshake; security depends on passphrase strength.
  • WPA2-Enterprise: uses 802.1X and EAP with per-user credentials.
  • WPA3: SAE (Simultaneous Authentication of Equals) replaces the pre-shared key handshake and resists offline dictionary attacks; DPP provides secure device onboarding.

Advantages (of the progression)

  • WPA2 with AES-CCMP is strong when the passphrase is strong.
  • WPA3 SAE removes the offline guessing risk for personal networks.

Disadvantages (of the progression)

  • WEP is insecure and WPA with TKIP is deprecated.
  • WPA2-Personal depends on the passphrase, and WPA3 transition modes can allow downgrades to WPA2.

Conclusion

Wi-Fi security moved from a broken cipher to strong AES and then to SAE. Each step was driven by a real attack, which is why current designs favour WPA3 where devices support it.

T30. IEEE 802.1X and EAP

Definition

IEEE 802.1X is a port-based access control standard that blocks a device from the network until it is authenticated. EAP (Extensible Authentication Protocol) is the framework that carries the authentication methods.

Introduction

802.1X applies to wired and wireless LANs. The port is open only for authentication traffic until the device proves its identity to a central server. This centralises control and makes per-user access possible.

Key points

  • Supplicant: the client device that asks for access and answers the challenge.
  • Authenticator: the switch or access point that controls the port; it passes only authentication traffic until success.
  • Authentication server: usually RADIUS, part of an AAA (authentication, authorisation, accounting) system, which makes the decision.
  • Pre-admission control: no data passes until the device is authenticated.
  • Device and user detection: identify by certificate, machine ID or user credentials.
  • Dynamic VLAN assignment: the server places each user in a VLAN according to its role.
  • EAP methods: EAP-TLS (certificates on both sides, the strongest); PEAP and EAP-TTLS (a TLS tunnel protects a password method); EAP-FAST.
  • Onboarding: guides new devices to install certificates.

Advantages

  • Per-user authentication and central control of policy.
  • Dynamic VLANs and role-based access reduce manual setup.

Disadvantages

  • Needs RADIUS and certificate infrastructure, which costs money and skill.
  • Complex to deploy and troubleshoot.

Conclusion

802.1X with EAP-TLS is the strongest access control for enterprise Wi-Fi, but it requires the infrastructure to support it.

Unit III

T31. IEEE 802.11i and the four-way handshake

Definition

IEEE 802.11i is the standard behind WPA2. It adds AES-based encryption, 802.1X authentication and a structured key hierarchy to WLAN security.

Introduction

802.11i replaced WEP's weak design. Its central mechanism is the four-way handshake, which lets the client and access point prove they know the same master key and then install fresh session keys, without sending the master key over the air.

Key points

  • PMK (pairwise master key): shared in advance (from the passphrase or from 802.1X) and never sent.
  • PTK (pairwise transient key): derived for each session from the PMK and fresh nonces; it protects unicast traffic.
  • GTK (group temporal key): protects broadcast and multicast traffic and is updated by a group key handshake.
  • Encryption: CCMP with AES (WPA2); TKIP for the older WPA.
  • Authentication: 802.1X with EAP for enterprises; PSK for homes and small offices.

Four-way handshake

Msg 1 AP -> STA : ANonce Msg 2 STA -> AP : SNonce, MIC Msg 3 AP -> STA : GTK (encrypted), MIC, install PTK Msg 4 STA -> AP : acknowledgement, install PTK
  • The PTK depends on ANonce, SNonce, the PMK and both MAC addresses, so each session has fresh keys.
  • The MIC proves that each side knows the PMK without revealing it.
  • An eavesdropper who captures the handshake can only attack the passphrase offline, so a weak passphrase is the real weakness.

Design for a small office

  • WPA2 or WPA3 with CCMP or GCMP; disable WEP and TKIP.
  • A long unique passphrase, or 802.1X with EAP-TLS where RADIUS exists.
  • 802.11w for protected management frames; a separate guest VLAN for visitors.
  • Change the router admin password, disable WPS and keep the firmware updated.

Advantages

  • AES-CCMP is strong and gives proper integrity.
  • The master key never crosses the air, and session keys change for every connection.

Disadvantages

  • Passphrase-based mode is open to offline guessing if the passphrase is weak.
  • Unpatched devices can suffer key reinstallation attacks.
  • Enterprise setup is complex and needs skilled staff.

Conclusion

802.11i gives WPA2 its strength through AES and a careful key hierarchy. Its real security still depends on passphrase strength and on keeping devices patched.

T32. Authentication in wireless networks

Definition

Wireless authentication confirms that a client may join the network. The methods range from none (open) to per-user certificates.

Introduction

The method chosen decides who may join, how credentials are handled and how far a compromise can spread. Each method suits a different setting, and the weakest method sets the level of the whole network.

Key points

  • Open authentication: the client says it wants to authenticate and the AP replies with success. It gives no security and must not be used.
  • WPA2/WPA3-Personal (PSK or SAE): the four-way handshake, or SAE in WPA3, proves knowledge of the shared passphrase without sending it.
  • WPA2-Enterprise: 802.1X with EAP, giving per-user credentials checked by RADIUS.
  • Accountability: enterprise mode records which user connected; personal mode cannot tell users apart.
  • Wi-Fi chalking: marks drawn on walls to advertise open or weakly protected networks; it shows why open authentication is dangerous.

Advantages

  • Enterprise mode gives per-user accountability and revocation.
  • Personal mode is simple for homes and small offices.

Disadvantages

  • Open authentication gives no protection.
  • Personal mode shares one passphrase among all users, so revoking one user means changing it for everyone.

Conclusion

Enterprise networks should use per-user authentication, and personal networks should use WPA2 or WPA3 with a strong passphrase. Open authentication has no place in a secured network.

T33. Layer 3 security mechanisms

Definition

Layer 3 security protects IP addressing, routing and traffic above the wireless link, using protocols and devices that control what packets may pass.

Introduction

Once a Wi-Fi link is secured, packets still travel across routers and networks. Layer 3 controls decide which traffic is allowed, how routes are trusted and how packets are protected end to end.

Key points

  • IPsec: AH provides integrity and authentication of packets; ESP provides confidentiality; IKE negotiates keys.
  • Static routing: fixed routes prevent a routing table from being poisoned by fake updates.
  • Routing authentication: HMAC on routing messages proves that updates come from a trusted router.
  • ACLs (access control lists): filter traffic by IP address, port and protocol.
  • Firewalls: enforce a boundary policy between networks.
  • IDS: watches traffic and reports anomalies.
  • Segmentation and VLANs: separate groups of users so a compromise stays local.
  • DHCP snooping and IP source guard: stop rogue DHCP servers and forged source addresses.
  • Port security, logging and monitoring: limit MAC addresses per port and keep records for investigation.

Advantages

  • IPsec protects traffic end to end across untrusted networks.
  • Static routes are predictable and easy to audit.

Disadvantages

  • Static routes need manual upkeep and do not adapt to failures.
  • IPsec depends on key management; weak keys or bad policies leave gaps.
  • ACLs and firewalls can be bypassed by address spoofing.
  • IDS can miss encrypted attacks and raise false alarms.
  • Segmentation fails if VLAN hopping is possible.

Conclusion

Layer 3 mechanisms control what traffic may travel and how it is protected. Their value depends on correct configuration and on key management.

T34. Bluetooth technology and security

Definition

Bluetooth (IEEE 802.15.1) is a short-range wireless technology in the 2.4 GHz band that uses frequency hopping over 79 channels to connect personal devices.

Introduction

Bluetooth links connect phones, headsets, wearables and car systems. Its security relies on pairing, which creates a shared link key, and on the security mode the devices enforce. Because it is cheap and everywhere, it is also a frequent target.

Key points

  • Piconet: one master and up to seven active slaves.
  • BR/EDR (Classic): carries audio and files. BLE: low energy, for sensors and wearables.
  • Legacy pairing: uses a PIN, which is weak against offline guessing.
  • Secure Simple Pairing (SSP, v2.1 onward): uses ECDH and four models: Numeric Comparison, Passkey Entry, Out-of-Band and Just Works.
  • Authentication: challenge-response with the link key.
  • Encryption: E0 in Classic (known weaknesses); AES-CCM in newer versions and BLE.
  • Security modes: Mode 3 enforces security at link level, so only authenticated devices communicate; Mode 4 is service-level security with SSP.
  • Attacks: bluejacking (unsolicited messages), bluesnarfing (unauthorised data access), bluebugging (control of phone functions), and eavesdropping or man-in-the-middle during weak pairing.
  • Securing a device: use SSP; set non-discoverable mode; remove unused pairings; apply updates; use Mode 3 or 4; switch Bluetooth off when unused.

Breach case study (illustrative)

  • A device left discoverable, paired with a weak PIN and never updated, is bluesnarfed and bluejacked.
  • Lessons: SSP, non-discoverable mode, updates and pairing hygiene.

Comparison with 802.11i

  • Both use AES-based encryption and authentication for short-range links.
  • 802.11i uses a four-way handshake and 802.1X for shared networks; Bluetooth uses pairing and link keys for personal devices.

Advantages

  • Low power and low cost; supported by almost every phone.
  • SSP gives strong pairing against eavesdropping.

Disadvantages

  • Short range.
  • Legacy pairing and E0 are weak.
  • Many known attacks affect older devices.

Conclusion

Bluetooth is secure when devices use SSP, enforce Mode 3 or 4 and stay updated. Its weak points are old pairing methods and devices left discoverable.

T35. WiMAX introduction, standards and Forum

Definition

WiMAX (Worldwide Interoperability for Microwave Access) is a standards-based wireless broadband technology based on the IEEE 802.16 family, offering an alternative to cable and DSL.

Introduction

The WiMAX Forum, formed in June 2001, promotes conformance and interoperability, certifies products and runs training. The 802.16 standards evolved from fixed, line-of-sight links to mobile, non-line-of-sight broadband.

Key points

  • 802.16 (2001): 10–66 GHz, line of sight, fixed.
  • 802.16a (2003): 2–10 GHz, non-line-of-sight.
  • 802.16d / 802.16-2004: fixed WiMAX, 2–11 GHz.
  • 802.16e-2005: mobile WiMAX, under 6 GHz, with handover.
  • 802.16m-2011: WirelessMAN-Advanced, about 100 Mbit/s for mobile and 1 Gbit/s for fixed.

  • Complementary use: operators use WiMAX to backhaul Wi-Fi hotspots.

Advantages

  • Long range and high speed without cabling.
  • Standards and certification make products interoperable.

Disadvantages

  • Higher frequencies need line of sight.
  • Spectrum licensing adds cost.
  • Lost ground to LTE in the mobile market.

Conclusion

WiMAX offered broadband over long distances and set the stage for mobile broadband. Its security history shows why later versions added mutual authentication and AES.

Unit IV

T36. WiMAX architecture, OFDM, layers and frames

Definition

WiMAX architecture is the set of network elements and protocol layers that provide broadband access, using OFDM for the radio link and a connection-oriented MAC.

Introduction

OFDM splits the channel into many narrow sub-carriers that resist multipath fading. The frame structure then carries data and bandwidth requests. Understanding the layers and frames shows where security is placed in the design.

Key points

  • Architecture: subscriber station, base station, Access Service Network (radio access) and Connectivity Service Network (IP, authentication, billing).
  • OFDM: 802.16-2004 uses 256 sub-carriers; 802.16e uses scalable OFDMA, which assigns sub-carriers to users.
  • Physical layer: transmission convergence and physical medium dependent sublayers, using QPSK, 16-QAM and 64-QAM.
  • Data link layer: the security sublayer at the bottom, the MAC common part (scheduling and connections), and the service-specific convergence sublayer.
  • Adaptive modulation: near subscribers use 64-QAM (6 bits per baud); medium distance uses 16-QAM (4 bits); far subscribers use QPSK (2 bits).
  • Classes of service: constant bit rate, real-time variable bit rate, non-real-time variable bit rate and best effort.
  • Generic frame (starts with 0): carries data, with an encryption flag, key information, length, connection ID and CRC.
  • Bandwidth-request frame (starts with 1): has a "bytes needed" field and no payload.
  • Security in frames: only payloads are encrypted, so addresses and connection IDs remain visible.

Advantages

  • OFDM is robust to multipath fading.
  • Adaptive modulation keeps the link working at varying distances.

Disadvantages

  • Complex design with signalling overhead.
  • Headers remain visible, which leaks some traffic information.

Conclusion

The WiMAX architecture trades complexity for robust, efficient radio. Its security is placed in the MAC sublayer, which protects payloads but not headers.

T37. WiMAX security architecture and PKM

Definition

WiMAX security architecture protects traffic and control messages in the MAC security sublayer. Privacy and Key Management (PKM) authenticates subscribers and distributes the keys that protect their traffic.

Introduction

Security associations hold the shared parameters for each connection, and PKM manages the keys that protect the traffic. The protocol version decides how strong the authentication is.

Key points

  • Security association (SA): holds the SAID, cryptographic suite, traffic encryption keys (TEKs) and initialisation vectors.
  • PKM: authenticates the subscriber and manages keys, using X.509 certificates, RSA and AES.
  • PKMv1: one-way; the base station authenticates the subscriber, not the reverse, so man-in-the-middle attacks are possible.
  • PKMv2 (802.16e): Privacy Key Management version 2, which provides two-way authentication.
  • RSA-based authentication: the manufacturer's X.509 certificate lets the base station encrypt an Authorisation Key (AK) for the subscriber.
  • EAP-based authentication: uses a certificate, SIM/USIM or username and password.
  • Authorisation: the base station checks the request with the AAA server, then returns the AK (encrypted), its lifetime and a SAID.
  • Data privacy: AES in CCM, CBC, CTR, ECB or Key Wrap modes, since DES is no longer considered secure.

Advantages

  • PKMv2 gives mutual authentication.
  • AES modes give strong confidentiality.

Disadvantages

  • PKMv1 is one-way and weak against impersonation.
  • Certificate management adds cost and overhead.

Conclusion

WiMAX security depends on PKM. PKMv2 with EAP and AES gives a much stronger design than PKMv1 with RSA and DES.

T38. WiMAX security risks (802.16-2004) and 802.16e

Definition

The security risks of 802.16-2004 are the weaknesses of fixed WiMAX. The 802.16e-2005 improvements are the fixes added for mobile WiMAX.

Introduction

Fixed WiMAX used weak ciphers and one-way authentication. Mobile WiMAX (802.16e) replaces them with stronger, mutual protections and adds secure handover, which is essential for a moving user.

Key points (802.16-2004 risks)

  • Weak encryption: DES with 56-bit keys.
  • One-way authentication in PKMv1: a rogue base station can impersonate a real one.
  • No mutual authentication: subscribers may send credentials to a fake station.
  • Replay exposure: some management messages lack replay protection, allowing forgery and session hijacking.
  • Unprotected control fields: some QoS and bandwidth-request fields are not integrity-protected.
  • Limited DoS protection: fake bandwidth requests and repeated re-authentication overload the base station.
  • No handover security: moving between base stations was not protected.

Key points (802.16e-2005 improvements)

  • AES-CCM encryption replaces DES.
  • PKMv2 with mutual EAP-based authentication.
  • AES-CMAC for control-message integrity and replay protection.
  • Handover security for soft and hard handover; sleep and idle modes; mobility up to about 120 km/h.

Design: secure WiMAX e-Governance protocol

  • PKMv2 with EAP-TLS and X.509 certificates for citizens and officers.
  • AES-CCM for traffic and AES-CMAC for control messages.
  • Certificate revocation checks; AAA logging of each access.
  • TLS at the application layer for citizen data, so the service is protected beyond the radio.

Improving key distribution without more overhead

  • Cache keys for fast re-authentication after handover.
  • Derive keys hierarchically from one authentication run.
  • Batch certificate checks and reuse session keys within their lifetime.

Advantages (of 802.16e)

  • Mutual authentication and AES encryption.
  • Secure handover for mobile users.

Disadvantages

  • Legacy devices still use DES.
  • Some DoS exposure remains.

Conclusion

The move from 802.16-2004 to 802.16e fixed the main cryptographic and authentication flaws. Operators must still disable legacy modes to get the benefit.

T39. GSM, UMTS and GPRS summary

Definition

GSM, GPRS and UMTS are successive cellular security architectures, each adding protections to the one before.

Introduction

A comparison table makes the progression clear. It shows how authentication, encryption and integrity improved from GSM to UMTS, and where each generation still has gaps.

Disadvantages (of GSM and GPRS)

  • One-way authentication and weak ciphers.
  • No integrity on signalling.

Conclusion

Each generation closed gaps left by the previous one, and UMTS is the first with mutual authentication and integrity. Its fallback to GSM is still a risk.

T40. VoIP security

Definition

VoIP (Voice over IP) carries voice as data packets over IP networks. Its security protects the signalling that sets up calls and the media that carries the voice.

Introduction

SIP handles signalling, meaning setting up, changing and ending calls. RTP carries the audio. Attackers can target either one, and they can also abuse the service for fraud, so VoIP needs protection at each point.

Key points

  • SRTP: encrypts and authenticates the media.
  • STUN and TURN: handle NAT traversal; these must be secured too.
  • Firewalls with IDS/IPS: filter and monitor SIP and RTP traffic.

Advantages

  • Cheap and flexible calls over existing IP networks.
  • Encryption with SRTP and TLS is available.

Disadvantages

  • Many deployments leave media unencrypted by default.
  • Toll fraud and spam are common and costly.

Conclusion

VoIP inherits both the convenience and the risks of IP. Secure signalling, encrypted media and monitoring make it safe.

T41. LTE security

Definition

LTE security is the set of mechanisms in 4G networks that provide mutual authentication, a key hierarchy, encryption and integrity for the UE, eNodeB and core network.

Introduction

LTE was designed with security as a core requirement. It uses EPS-AKA for mutual authentication and a key hierarchy that separates keys for signalling and for user data. It still has known weaknesses, especially in its fallback and in the interconnects.

Key points

  • Architecture: UE and eNodeB; the Evolved Packet Core contains the MME (mobility and signalling security), HSS (subscriber data and keys), S-GW and P-GW (user data).
  • EPS-AKA: the HSS and USIM share the long-term key K; both prove knowledge of K, so the authentication is mutual; the result is KASME, passed to the MME.
  • Key hierarchy: the MME derives NAS keys for signalling; the eNodeB derives KeNB for user data, which changes at handover; AS keys come from KeNB.
  • Encryption algorithms: EEA0 (null), EEA1 (SNOW 3G), EEA2 (AES), EEA3 (ZUC).
  • Integrity algorithms: EIA1 (SNOW 3G), EIA2 (AES), EIA3 (ZUC).
  • PDCP: applies the keys to user data; sequence numbers prevent replay.
  • Vulnerabilities: IMSI catchers and downgrade attacks to 2G or 3G; null encryption (EEA0) if the UE does not reject it; SS7 and Diameter roaming links allow tracking; jamming.
  • Mitigation: temporary identities (GUTI) so the IMSI is rarely sent; reject null ciphers and 2G downgrades; integrity-protected signalling; firewall the SS7 and Diameter interconnects.
  • Crypto choice: AES with hardware support is fast; SNOW 3G and ZUC run well in software; null encryption is the fastest but gives no confidentiality.
  • LTE vs WiMAX: LTE has mutual authentication from the start and a key hierarchy; WiMAX 2004 had one-way authentication.
  • Hybrid WiMAX–LTE design: one identity and key management (common AAA and EAP); secure handover with 802.21; AES on both; avoid PKMv1 and A5; keep key hierarchies separate so keys are not reused.

Advantages

  • Mutual authentication and AES-based protection.
  • The key hierarchy limits damage from one key leak.

Disadvantages

  • IMSI catching and downgrade attacks remain.
  • SS7 and Diameter interconnects are weak points.
  • The null cipher option must be blocked on every device.

Conclusion

LTE is much stronger than GSM and 3G because of mutual authentication and its key hierarchy. Its remaining risks lie in the fallback to older networks and in signalling between operators.

T44. Execution environments and sandboxing

Definition

An execution environment is the context in which active content (applets, scripts, controls and app code) runs. Sandboxing isolates that content so that a flaw does not reach the rest of the system.

Introduction

Environments differ in how strongly they isolate code, from the Java sandbox and browser rules to OS sandboxes and hardware-isolated TEEs. The stronger the isolation, the less damage a compromised app can do.

Key points

  • Java sandbox: the class loader, bytecode verifier and security manager restrict file, network and system access.
  • JavaScript in browsers: the same-origin policy stops a page from reading another site's data; Content Security Policy limits which resources can load.
  • ActiveX: signed controls with no sandbox, so trust in the signer is the only protection.
  • Mobile apps: each app runs in its own OS sandbox with its own UID.
  • TEE (trusted execution environment): a hardware-isolated area for sensitive code and keys, such as ARM TrustZone; secure enclaves are similar.
  • Rich execution environment (REE): the normal operating system, which has the larger attack surface.
  • Least privilege: an app receives only the permissions it needs.
  • Combined effect: sandboxing and least privilege together cap the damage a compromised app can do.

Advantages

  • Contains damage from a flawed or malicious app.
  • TEEs protect keys even if the main OS is compromised.

Disadvantages

  • Sandboxes can be escaped through unpatched flaws.
  • Strict isolation limits usability and performance.
  • ActiveX has no sandbox at all.

Conclusion

Sandboxing is the main way modern platforms limit damage. Its strength depends on how isolated the environment is and on the least privilege given to each piece of code.

Unit V

T45. Validation of active content

Definition

Validation of active content checks that downloaded code is authentic, unchanged and safe before or while it runs.

Introduction

Validation combines three checks: signing (who wrote the code), static analysis (what the code contains) and dynamic analysis (what the code does). Each check catches different problems, so they are used together.

Key points

  • Code signing: a digital signature proves who wrote the code and that it was not changed afterwards. Certificates follow the X.509 standard.
  • Bytecode verification: checks that code follows the language's safety rules before it runs.
  • Static analysis: reviews code without running it, looking for unsafe calls, hard-coded secrets and insecure patterns.
  • Dynamic analysis: runs the code in a monitored environment and observes its behaviour, catching runtime problems static analysis misses.
  • Input sanitisation and safe JavaScript: avoid eval, use strict mode and validate all input.
  • Dependency checks: software composition analysis and an SBOM (software bill of materials) find vulnerable libraries.
  • SSL pinning: limits trust to a known certificate or key (see T20).
  • Safe source: official app stores are the safest place to get apps.

Advantages

  • Catches tampered and unsafe code before users are harmed.
  • Static and dynamic checks complement each other.

Disadvantages

  • Static analysis gives false positives that need manual review.
  • Dynamic analysis only covers the paths it actually runs.
  • Code signing proves the source, not that the code is safe.

Conclusion

Validation gives confidence that code is authentic and behaves as expected. It works best as a combination of signing, static and dynamic checks.

Unit V

T46. Detection of attacks on downloadable apps

Definition

Attack detection on downloadable apps is the monitoring of app and device behaviour to spot malicious activity, followed by a response to it.

Introduction

Detection methods differ in what they know: known signatures, learned normal behaviour, or defined rules. Each method has a different balance between catching new attacks and raising false alarms.

Key points

  • Signature-based: matches known malware patterns; accurate for known threats, but misses new ones.
  • Anomaly-based: learns normal behaviour and flags deviations; finds new attacks but gives more false alarms.
  • Specification-based: checks behaviour against defined rules; few false alarms, but the rules are hard to write.
  • HIDS (host-based): monitors one device or app.
  • NIDS (network-based): monitors network traffic; cannot read encrypted content.
  • Step 1, collect data: system calls, permissions used, connections made, log spikes.
  • Step 2, compare: against signatures or the normal profile.
  • Step 3, decide: whether the behaviour is an attack.
  • Step 4, respond: alert, block, quarantine or remove the app.
  • Step 5, learn: update signatures and feed the findings into incident response.
  • Tools: IDS and IPS, SIEM for logs, SAST and DAST for testing, RASP at runtime.
  • Sideloading risk: no store vetting, unknown publisher, malware that bypasses updates, and no revocation. Mitigate by disabling unknown sources, allowing only trusted stores and using MDM.

Advantages

  • Signature detection is fast and accurate for known threats.
  • Anomaly detection can catch new attacks.

Disadvantages

  • Signatures miss new malware.
  • Anomaly detection raises false alarms.
  • Network-based detection cannot see encrypted content.

Conclusion

No single method is enough. Combining signature and anomaly detection, with host and network monitoring, gives the best coverage for downloadable apps.

B1. Analyse the impact of default passwords on Wi-Fi routers (8 marks)

Definition

Default router passwords are factory credentials that are never changed, so anyone who knows them can control the router.

Key points

  • Default passwords are printed on labels or published in online lists.
  • An attacker can take admin control, change DNS settings to redirect traffic, or join the network without a passphrase.
  • Impact: full control of the network, which exposes every device on it.
  • Mitigation: change the admin password at setup; set a unique Wi-Fi passphrase; disable WPS; update firmware; disable remote administration unless needed.

Advantages / Disadvantages

  • Advantage of changing defaults: removes the easiest attack.
  • Disadvantage: users forget custom passwords, so a reset may be needed.

B2. Explain the SS7 attack (MCQ and short)

Definition

SS7 is the signalling system that connects operator networks. An SS7 attack abuses the trust that operators place in each other's messages.

Key points

  • The trust model assumes other operators' messages are genuine.
  • An attacker with SS7 access can request a subscriber's location, intercept calls and SMS, or divert messages.
  • Defence: operators filter SS7 messages at their borders; block requests from unexpected origins; use Diameter-based and encrypted interconnects where possible.

Advantages / Disadvantages

  • Advantage of defence: stops many tracking attacks.
  • Disadvantage: SS7 is old, so full fixes are slow and costly.

B3. Secure development lifecycle (16-mark case)

Definition

A secure development lifecycle (SDL) builds security into every phase of app creation.

Key points

  • Design: threat modelling and least-privilege design.
  • Development: secure coding, input validation, Keystore use and no secrets in code.
  • Testing: static analysis, dynamic analysis, penetration testing and dependency checks.
  • Release: signed builds and a security review gate.
  • Operations: monitoring, patching, incident response and a vulnerability-reporting channel.
  • Each phase has a clear output, so security is checked before the next phase starts.

Advantages / Disadvantages

  • Advantage: finds flaws early and cheaply.
  • Disadvantage: adds time and needs trained staff.

B4. BYOD and mobile device management

Definition

BYOD (Bring Your Own Device) lets staff use personal phones on company networks. MDM (Mobile Device Management) enforces policy on those devices.

Key points

  • MDM enforces passcodes, encryption, approved apps, remote wipe and access control.
  • Containers separate work data from personal data on the same device.
  • Trade-off: employee privacy against company control.

Advantages / Disadvantages

  • Advantage: lower device cost for the company; staff productivity.
  • Disadvantage: mixes personal and corporate data; limited company control.

B5. Smishing and phishing

Definition

Phishing uses fake email to steal credentials. Smishing uses fake SMS messages for the same purpose.

Key points

  • Both create urgency (for example "your account is locked") and link to a fake login page.
  • Defence: check the sender; do not click links in unexpected messages; use two-factor authentication; report the message.

Advantages / Disadvantages

  • Advantage of awareness training: lowers click rates.
  • Disadvantage: attacks keep changing, so training must repeat.

B6. Mobile security tools (APKTool, MobSF, Frida, ProGuard)

Definition

These are tools used to analyse and protect Android apps.

Key points

  • APKTool: decompiles and rebuilds APKs for review.
  • MobSF: an automated static and dynamic analysis framework.
  • Frida: hooks running code to observe runtime behaviour.
  • ProGuard: shrinks and obfuscates Java code, making reverse engineering harder.
  • Use the first three only on apps you are authorised to examine; use ProGuard to protect your own release builds.

Advantages / Disadvantages

  • Advantage: flaws are found before release.
  • Disadvantage: the same tools can be misused by attackers.

B7. Google Play Protect and mobile threat defence

Definition

Google Play Protect scans apps for malware. Mobile threat defence (MTD) products extend this protection in enterprises.

Key points

  • Play Protect scans apps on the device and in the Play Store and warns about risky apps.
  • MTD adds network monitoring and remote actions for managed devices.
  • Limit: strong on known threats and behaviour patterns, but cannot stop every new attack.

Advantages / Disadvantages

  • Advantage: automatic, built in and low effort.
  • Disadvantage: detection lags new malware.

B8. VPN and its purpose

Definition

A VPN (virtual private network) creates an encrypted tunnel from the device to a trusted endpoint.

Key points

  • Traffic on an untrusted network, such as public Wi-Fi, cannot be read or altered on the way.
  • Protects confidentiality and integrity in transit.
  • Protects only the tunnel; the endpoint and the app still need their own protection.

Advantages / Disadvantages

  • Advantage: safe use of public Wi-Fi.
  • Disadvantage: the VPN provider or endpoint must be trusted; adds some latency.
